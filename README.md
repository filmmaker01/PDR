# PDR Platform — Telegram Mini App для PDR-мастеров

Единое Telegram Mini App с двумя самостоятельными разделами — **«Обучение»** (курс из трёх этапов, практика, экзамены, кураторы, клуб) и **«Мастерская»** (CRM: клиенты, автомобили, заказы, календарь, сметы, оплаты, сотрудники, аналитика) — плюс **веб-админка** платформы.

Версия 1.0 реализована целиком по этапам 0–16 из `docs/12-roadmap.md`: обучение, CRM, платформа и админка работают, покрыты тестами и готовы к пилоту. Что входит в 1.0 и что сознательно оставлено на потом — в `docs/01-scope.md`.

## Ключевые решения (кратко)

- **Модульный монолит**: один backend (NestJS + TypeScript), одна база PostgreSQL, отдельный процесс worker для фоновых задач из того же кода.
- **Три продукта — три независимых доступа**: курс, CRM, клуб. Окончание курса не лишает мастера его CRM; отзыв клуба не трогает курс.
- **Один пользователь — много контекстов**: роли платформы (администратор, куратор), зачисления на курс (ученик), членство в мастерских (владелец, сотрудник) хранятся отдельно.
- **Изоляция мастерских на уровне данных и кода**: `workspace_id` у всех CRM-сущностей, проверка членства при каждом запросе, единый репозиторный слой, который не умеет читать без `workspace_id`.
- **Опубликованная программа фиксируется версией**: правки курса не ломают прогресс текущих групп.
- **Деньги в минимальных единицах**, время в UTC, смета версионируется, оплаты не редактируются, а корректируются записями.
- **Проверка доступа на сервере** при выдаче видео, отправке работы, запуске экзамена, выдаче ссылки на файл — не только в интерфейсе.

## Запуск локально

```bash
pnpm install
pnpm --filter @pdr/shared build          # общий пакет собирается в CJS и ESM
./infra/scripts/dev-up.sh                # база, хранилище, миграции, сиды
pnpm dev                                 # api + miniapp + admin
pnpm --filter @pdr/api dev:worker        # фоновые задачи (отдельный процесс)
```

Без Docker достаточно локального PostgreSQL 16 и `STORAGE_DRIVER=local`.
Переменные окружения описаны в `apps/api/.env.example`; конфигурация проверяется при старте.

## Проверки

```bash
pnpm lint          # ESLint, 0 предупреждений
pnpm typecheck     # tsc по всем пакетам
pnpm test:unit     # модульные тесты
pnpm test:integration   # интеграционные, нужна PostgreSQL (TEST_DATABASE_URL)
pnpm build         # сборка всех приложений
pnpm format:check  # Prettier
```

Сквозные сценарии F1–F10 из `docs/07-user-flows.md` проходят в `apps/api/test/e2e-flows.spec.ts`,
обязательные проверки безопасности — в `apps/api/test/security.spec.ts`.
Нагрузочная проверка: `infra/load/` (k6, запускается на staging вручную).
