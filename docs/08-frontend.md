# 08. Экраны Mini App и веб-админки

## Общие принципы

- **Mini App** — мобильный интерфейс в Telegram (iOS, Android, Desktop). Тема из `--tg-theme-*`, `MainButton`/`BackButton` Telegram SDK там, где это естественно (отправка формы, назад), `HapticFeedback` на подтверждениях, `viewport` с учётом клавиатуры. Все экраны работают при ширине 320px.
- **Админка** — десктопный веб на Mantine, таблицы с фильтрами и сохранёнными состояниями, боковое меню.
- Оба клиента: TanStack Query с оптимистичными обновлениями там, где безопасно (отметка урока, статус записи), и без них для денег и статусов заказа. Ошибки API показываются сообщением сервера.
- Состояния каждого экрана: загрузка (скелетоны), пусто (с действием), ошибка (повтор), «нет доступа» (объяснение и что делать).
- Деньги форматируются из minor units с валютой мастерской; даты — в часовом поясе мастерской (CRM) или устройства (обучение).

| Раздел | Экраны | Содержание |

## Компоненты `packages/ui` (Mini App)

Список, карточка, чипы фильтров, поле поиска, форма (react-hook-form + zod), выбор даты/времени с шагом, выбор длительности, денежное поле (ввод в рублях → minor), загрузчик медиа (очередь, прогресс, повтор, миниатюры), галерея с zoom, статус-бейдж, таймлайн истории, пустое состояние, шторка выбора (bottom sheet), подтверждение действия, скелетоны.

## Offline и сеть

Mini App не работает полностью офлайн, но: очередь загрузок файлов переживает потерю сети и повторяет части; формы сохраняют черновик в памяти при уходе на другой экран; идемпотентные ключи генерируются при открытии формы.

## Сквозной сценарий (этап 17)

Один поток без повторного ввода данных:

```
Новое обращение
  → клиент (существующий или свободный контакт) и машина
  → фото с камеры
  → выбор детали на интерактивной схеме кузова
  → разметка конкретной вмятины на фотографии
  → предварительная оценка (вручную / по параметрам / по фотографии)
  → «Ждёт решения» или «Перезвонить» с датой
  → запись в календарь (клиент и авто заводятся в этот момент)
  → «Создать заказ» — повреждения, фото и оценки переезжают в заказ
  → работа по заказу: смета, оплата, статусы
```

Три отдельные сущности с дублированием намеренно не создавались: повреждение,
снимок и оценка принадлежат либо обращению, либо заказу, и при конверсии
меняют владельца, а не копируются.

## Компоненты `@pdr/ui` для схемы и разметки

- `CarScheme` — вид сверху, инлайновый SVG. Крупные цели для пальца: капот,
  крыша, багажник, бамперы, крылья, двери, пороги. Мелкие и редкие элементы
  (стойки A/B/C, рейлинги, дверь багажника) — кнопками под схемой: на виде
  сверху они заняли бы полосы в несколько пикселей. Схема помещается в экран
  телефона целиком (`max-height: 58vh`), `touch-action: manipulation`.
- `PhotoMarkup` — слой разметки поверх снимка. Координаты нормированы к 0–1,
  рисуются в системе координат самой фотографии: круг не превращается в овал
  на широком кадре. `touch-action: none` и захват указателя — линия не рвётся,
  когда палец уходит за край. `renderMarkupToBlob` сводит снимок с разметкой в
  картинку для печати и выгрузки, не трогая оригинал.
