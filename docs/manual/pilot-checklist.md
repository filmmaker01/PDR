# Чеклист запуска пилота

Проверки перед тем, как пускать в продукт первых мастеров. Автоматические пункты закрыты тестами, ручные требуют человека и устройств.

## Автоматически (CI, `pnpm test:unit` и `pnpm test:integration`)

- [x] Изоляция мастерских: чужие заказы, клиенты и файлы недоступны ни по идентификатору, ни по ссылке (`test/security.spec.ts`, `crm-*.spec.ts`).
- [x] Администратор платформы без членства не видит данные мастерской.
- [x] Закрытый этап недоступен через прямой запрос к API (`learning-progress.spec.ts`).
- [x] Отозванная сессия и бан перестают работать на следующем запросе (`security.spec.ts`, `auth.spec.ts`).
- [x] Повторный запрос с тем же ключом идемпотентности не создаёт дубль заказа, оплаты, сдачи и попытки экзамена.
- [x] Двойное бронирование невозможно даже при гонке: ограничение на уровне базы (`crm-appointments.spec.ts`).
- [x] Записи об оплатах нельзя изменить или удалить через API.
- [x] Даты и календарь считаются в часовом поясе мастерской (`datetime.test.ts`, `crm-appointments.spec.ts`).
- [x] Клуб: заявка без доступа отклоняется, с доступом одобряется, отзыв исключает, продление позволяет вернуться (`club.spec.ts`).
- [x] Выгрузка CRM открывается в Excel: UTF-8 с BOM, разделитель «;», суммы с копейками (`csv.test.ts`, `export-privacy.spec.ts`).
- [x] Уведомление заблокировавшему бота пользователю не ломает бизнес-операцию (`e2e-flows.spec.ts`, `notifications-audit.spec.ts`).
- [x] Сценарии F1–F10 проходят целиком (`e2e-flows.spec.ts`).

## Вручную перед пилотом

- [ ] Mini App открывается и работает в Telegram iOS, Android, Desktop и в веб-версии: вход, видео, камера, загрузка фото, приглашение сотрудника.
- [ ] Прерванная загрузка фотографий (отключить сеть на 30 секунд, свернуть приложение) продолжается без потери уже загруженных файлов.
- [ ] Мастерская с часовым поясом UTC+7 при сервере в UTC: «сегодня», календарь и напоминания совпадают с ожиданиями мастера.
- [ ] Восстановление базы из резервной копии на staging по `infra/backup/restore.sh`: зафиксировать объём дампа и время восстановления.
- [ ] Принудительная остановка worker: после перезапуска незавершённые задачи выполняются, дашборд показывает состояние.
- [ ] Нагрузочная проверка на staging: `k6 run infra/load/read-load.js` (чтение списков) и 50 одновременных загрузок фотографий — время ответа не деградирует.
- [ ] Sentry получает ошибки с `requestId`, в логах нет персональных данных и токенов.
- [ ] Бот production: отдельный токен, webhook с секретом, бот — администратор группы клуба с правами приглашать и исключать.

## Production-окружение

- [ ] Домены и TLS: `app.<домен>` (Mini App), `admin.<домен>`, `api.<домен>`.
- [ ] Переменные окружения заполнены по `.env.example`; `APP_ENV=production`, `STORAGE_DRIVER=s3`, `VIDEO_PROVIDER=kinescope`, заданы `SESSION_JWT_SECRET`, `TELEGRAM_*`, `S3_*`, `BACKUP_S3_BUCKET`.
- [ ] Роль базы для приложения не имеет прав `UPDATE`/`DELETE` на `payment_entries`, `audit_log`, `order_status_history`, `reviews`; миграции выполняются отдельной ролью.
- [ ] Версионирование включено на bucket файлов и на bucket резервных копий.
- [ ] Резервное копирование запущено по расписанию, в дашборде видна свежая копия.
- [ ] Демо-данные (курс и тестовая мастерская) не попадают в production: сид запускается только на staging.
