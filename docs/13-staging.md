# Staging и продуктовый QA

Документ описывает, как поднять полное окружение продукта на одной машине,
что в нём уже есть, что проверено вручную через интерфейс и чего не хватает
до рабочего запуска.

## 1. Что такое это окружение

Staging — полная копия продукта: тот же код, та же схема базы, те же миграции,
те же фоновые задачи. Отличий от production ровно три, и все они включаются
явно переменными окружения:

| Что | Staging | Production |
|---|---|---|
| Вход | демо-аккаунты без Telegram (`DEMO_LOGIN_ENABLED=true`) | только Telegram |
| Файлы | локальный диск (`STORAGE_DRIVER=local`) | S3 |
| Видео | заглушка (`VIDEO_PROVIDER=mock`) | Kinescope |

`DEMO_LOGIN_ENABLED=true` при `APP_ENV=production` запрещён проверкой
конфигурации — приложение не запустится. Послабления по хранилищу и видео
действуют только при `APP_ENV=staging` **и** включённом демо-входе: как только
демо-вход выключен, staging требует S3, Kinescope и Telegram так же, как
production.

## 2. Запуск

Требуется PostgreSQL 16 (с расширением `btree_gist`), Node 22, pnpm 9.

```bash
cp apps/api/.env.staging.example apps/api/.env.staging
# заполнить SESSION_JWT_SECRET и DEMO_LOGIN_SECRET
./infra/scripts/staging-up.sh          # база, миграции, демо-данные, API, worker, фронтенды
./infra/scripts/staging-down.sh        # остановить
./infra/scripts/staging-up.sh --no-seed # перезапуск без пересоздания данных
```

Скрипт поднимает:

| Компонент | Адрес по умолчанию |
|---|---|
| Mini App | http://localhost:5173 |
| Админка | http://localhost:5174 |
| API | http://localhost:3000 |
| Swagger | http://localhost:3000/docs |
| Проверка живости | http://localhost:3000/health/ready |

Логи процессов — в `.staging-logs/`.

Worker запускается после API: pg-boss создаёт свою схему при первом старте, и
два процесса, стартующие одновременно, мешают друг другу.

## 3. Вход

Mini App вне Telegram показывает экран выбора демо-аккаунта. Экран закрыт
секретом: открывать надо ссылкой `http://localhost:5173/?demo=<DEMO_LOGIN_SECRET>`
— секрет запоминается в браузере, дальше достаточно обычного адреса.
Без верного секрета сервер отвечает «не найдено» и экран предлагает открыть
приложение в Telegram.

Демо-аккаунты (`prisma/seed-staging.ts`):

| Ключ | Кто | Что видно |
|---|---|---|
| `student` | Игорь Ученик | этап 1 пройден, этап 2 открыт, есть возвращённая работа |
| `student_new` | новый ученик | курс только начат, пустые состояния |
| `curator` | куратор | очередь проверок с работой и практическим экзаменом |
| `master` | владелец мастерской | заказы, календарь, сметы, оплаты, аналитика |
| `employee` | сотрудник | только свои заказы, без аналитики и журналов |
| `admin` | администратор | доступы, курс, группы, клуб, выгрузки |
| `expired` | владелец с истёкшим доступом | режим только для чтения |

## 4. Демо-данные

`pnpm --filter @pdr/api seed:staging` очищает базу и наполняет её заново
(в `production` отказывается работать). Создаётся:

- курс из трёх этапов: 7 уроков, 2 практических задания, 2 теста, экзамен;
- поток «Осень» с двумя учениками и полной историей прогресса;
- мастерская «Кузовной цех на Ленина»: 8 позиций прайса, 8 клиентов,
  10 автомобилей, 10 заказов во всех статусах, сметы, оплаты (включая
  корректировку), 12 фотографий, 7 записей в календаре;
- вторая мастерская с истёкшим доступом — для проверки режима чтения;
- доступы, участие в клубе, запись о резервной копии.

Записи в календаре создаются в часовом поясе мастерской, а не сервера:
иначе «сегодня» на сервере в UTC и «сегодня» в Москве расходятся на день.

## 5. Что проверено через интерфейс

`node infra/qa/flows.mjs` — сценарии F1–F10, `node infra/qa/audit.mjs` —
навигация кликами, состояния интерфейса, ширины 360/390/1280/1440,
снимки экранов в `.qa-screens/`. Оба прогона выполняются в реальном браузере
(Playwright + Chromium) и фиксируют ошибки консоли и ответы HTTP ≥ 400.

Проверено: вход, карта курса, этап, урок, задание, экзамен, очередь куратора,
карточка работы, все вкладки мастерской, все разделы владельца, карточка
заказа со всеми вкладками, создание заказа, ограничения роли сотрудника,
режим истёкшего доступа, клуб, уведомления, несуществующий адрес,
все 13 разделов админки.

## 6. Чего нет без внешних ключей

| Возможность | Что нужно |
|---|---|
| Вход из Telegram, бот, уведомления, напоминания | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET`, публичный HTTPS-адрес |
| Клуб: автоматическое одобрение заявок и исключение | `TELEGRAM_CLUB_CHAT_ID`, `TELEGRAM_CLUB_INVITE_LINK` |
| Видеоуроки | `KINESCOPE_API_KEY`, `KINESCOPE_PARENT_ID`, `VIDEO_PROVIDER=kinescope` |
| Файлы в облаке вместо диска | `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` |
| Резервные копии в облако | `BACKUP_S3_BUCKET` |
| Сбор ошибок | `SENTRY_DSN` |

Без Kinescope на экране урока показывается объяснение вместо плеера, а порог
просмотра в демо-данных снят: иначе урок нельзя отметить пройденным.
